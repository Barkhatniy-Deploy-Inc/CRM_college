# Передача инфраструктурных задач

## Что подготовлено

- Базовый Compose публикует только gateway на loopback; дополнительные порты находятся в отдельном debug-файле. PostgreSQL всегда доступен контейнерам на `db:5432`.
- При первом запуске `./scripts/local.sh init` создаёт локальные секреты; PostgreSQL инициализирует имена баз из Compose. Изменение этих имён и пароля не меняет уже существующий volume.
- CI проверяет конфигурацию Compose, сборку образов, применение миграций Alembic к пустому PostgreSQL и health-маршруты через gateway. Конфигурационные проверки можно запустить командой `python3 -m unittest discover -s scripts/tests -v` без запущенного Docker Engine.
- 31.10.2026 на локальном Docker проверены сборка четырёх образов, применение миграций всех сервисов к отдельным пустым базам и health-маршруты gateway. Тестовые контейнеры и volume удалены после проверки; существующие данные не использовались.
- Подготовлен постоянный локальный PostgreSQL volume с тремя базами и применёнными миграциями. Команды доступа, резервирования и восстановления — в [руководстве для Глеба](POSTGRESQL_LOCAL_RUNBOOK.md). Проверка восстановления архивов всех трёх баз выполнена отдельно на PostgreSQL в tmpfs с контрольными данными и добавлена в CI.

## Следующие задачи

1. **Глеб:** инвентаризировать существующие SQLite и PostgreSQL в каждом окружении; подготовить и отрепетировать перенос SQLite с подсчётом записей и проверкой связей и последовательностей. Миграции пустой схемы не переносят данные. При появлении настоящих данных повторить проверку восстановления и согласовать хранение копий.
2. **Глеб и Артём:** согласовать заполнение `owner_id` для старых технологических карт; без него обычный пользователь не увидит такие карты. Проверить остальные расхождения схем перед использованием Alembic на существующих базах. Не выполнять автоматический `stamp head` неизвестной базы.
3. **Ярослав и Артём:** расширить CI сквозными сценариями входа, прав, работы с расписанием, технологических карт и авторизованного WebSocket. Текущие health-проверки не подтверждают эти сценарии.
4. **На будущее:** после выбора места размещения подготовить production-конфигурацию и правила доступа, TLS, управление секретами, отдельные роли БД и автоматическое резервирование. Сейчас согласовано локальное окружение.
5. **Артём и Ярослав:** разобрать результаты `npm audit` в чистом окружении и обновить зависимости с проверкой совместимости. При сборке 31.10.2026 npm сообщил о 28 уязвимостях во всём дереве зависимостей, включая одну критическую; применимость к production ещё не установлена.

Общие приоритеты и критерии приёмки: [аудит и план команды](TEAM_AUDIT_AND_POSTGRESQL_PLAN_2026-10-31.md). Инструкция по локальному запуску: [LOCAL_DEVELOPMENT.md](LOCAL_DEVELOPMENT.md).
