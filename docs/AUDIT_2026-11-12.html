01 / Главный вывод

Состояние поместья

Вердикт дворецкого
Проект работает. Но «работает» и «можно доверить ему персональные данные» — разные титулы, милорд.

Три проблемы уровня P0: анонимная выдача контактов участников, чужие занятия в «личном» календаре и API техкарт без согласованной проверки роли. Четыре сценария были воспроизведены локально, включая подмену админской сессии при создании пользователя.

02 / P0 · Перед публикацией

Три двери без замка

Это не прогноз погоды и не фантазия ревизора. Для каждого пункта есть конкретный маршрут и локальное подтверждение.

Дело 01P0 · Подтверждено

Список участников открыт всем

Гостей даже не спросили, есть ли у них приглашение.

Косяк: GET списка участников группы не требует авторизации и отдаёт ФИО, email и Telegram ID. Анонимный запрос к тестовой группе вернул 200 и все эти поля. Если в БД реальные записи, это прямая выдача персональных данных.

Где смотреть

backend/schedule/routers/participants.py:15–17
backend/schedule/database/models.py:125–135

Что сделать

Закрыть endpoint авторизацией и доступом по группе; для публичного списка создать отдельный ответ без контактов. Тесты: аноним 401, чужой пользователь 403.

Дело 02P0 · Подтверждено

Личный календарь оказался общим

«Моё расписание» — смелое название для расписания всех подряд.

Косяк: `/api/schedule/calendar/me.ics` принимает пользователя, но функция генерации игнорирует его ID и забирает до 1000 занятий без фильтра. JWT постороннего тестового пользователя получил 200 и чужое событие.

Где смотреть

backend/schedule/routers/calendar.py:9–12
backend/schedule/services/calendar_service.py:7–12

Что сделать

Определить «моё» через группу, участие или преподавателя; фильтровать запрос по пользователю. Закрепить тестом отсутствие чужих событий.

Дело 03P0 · Подтверждено

Студенту не показывают дверь — но она открыта

Скрыть кнопку — не то же самое, что поставить охрану.

Косяк: UI скрывает раздел техкарт от студента, а POST `/api/techcards` требует лишь валидный JWT. Запрос с ролью student создал карту: 201. Если техкарты положены только преподавателям и администраторам, права обходятся прямым API-запросом.

Где смотреть

backend/techcard/routers/techcard_router.py:106–128
frontend/src/core/layouts/DefaultLayout.vue:73

Что сделать

Согласовать матрицу ролей и проверять её на сервере для create/list/get/update/download. Если студентам карты разрешены — честно отразить это в UI и требованиях.

03 / P1 · Следом за пожарными

Не горит? Нет, просто тлеет

Семь пунктов, из которых первый уже проверен на живом API приложения с тестовой БД. Остальные вытекают из потока кода и требуют регрессионных сценариев.

04 / P1 · Подтверждено

Админ создаёт студента — и сам становится студентом

Без фокусов: админ-панель вызывает `/auth/register`; endpoint выдаёт новому аккаунту токены и заменяет cookie текущего браузера. В тесте после создания студента `/auth/me` вернул уже студента, а не администратора. Развести публичную регистрацию и отдельный защищённый admin-create без Set-Cookie.

frontend/src/store/admin.js:86–90 · backend/auth/routers/auth.py:27–70
05 / P1

Отозвали доступ, забыли про access JWT

Смена роли, пароль и выход отзывают refresh-токены; ранее выданный access-токен остаётся пригодным до истечения срока — по умолчанию до 15 минут. Для немедленного отзыва нужна проверка сессии/версии токена.

backend/auth/services/token_service.py:100–106 · backend/schedule/dependencies.py:9–38
06 / P1

HttpOnly есть, а токены всё равно в JSON

Login, register и refresh возвращают access и refresh токены в теле ответа. Любой JS с доступом к ответу видит их: хорошую идею с HttpOnly здесь сопровождают открытым окном.

backend/auth/database/schemas.py:73–78 · backend/auth/routers/auth.py:65–69
07 / P1

Расписание терпит двойную бронь

Проверка свободной аудитории и запись разделены; конкурентные запросы могут пройти одновременно. Импорт обходит эту проверку совсем, а счётчики созданных групп считают после присвоения ID. Нужны инварианты, транзакционная стратегия и тесты импорта.

backend/schedule/api/slots_api.py:11–39 · backend/schedule/services/schedule_importer.py:65–129
08 / P1

Три базы, три представления о человеке

Auth хранит роль и статус, schedule — другую таблицу пользователей, techcard — числовые ссылки без межсервисной целостности. Подписка Telegram ищет ID из auth в schedule: если записи нет, будет 404. Требуется один источник истины и договорённость о синхронизации.

backend/schedule/routers/notifications.py:15–20 · backend/techcard/database/models_techcard.py:12–19
09 / P1

WebSocket зовёт за свежими данными — к старому кэшу

Списки расписания и групп кэшируются 30/60 секунд без явной инвалидации при записи. Клиент после WS-события может снова увидеть старое. Кэш и список WS-соединений — в памяти одного процесса, что не переживёт масштабирование.

backend/schedule/routers/schedule.py:48–67 · backend/schedule/main.py:63–70
10 / P1

Вычислительный банкет за чужой счёт

Экспорт XLSX/PDF не требует входа и не ограничен частотой и диапазоном; при запросе списка с датами параметр limit фактически игнорируется в пользу 2000 строк. Excel целиком читается и парсится в async-обработчике. Поставить лимиты и вынести тяжёлую работу.

backend/schedule/routers/export.py:9–45 · backend/schedule/api/schedule_api.py:24–38,110–113
04 / Vue · Облицовка и механика

Лоск есть. Под ним — проводка.

Ниже не придирки к цвету кнопок: эти мелочи меняют данные, которые видит человек, и иногда сообщают ему откровенную неправду.

Сеанс по слухам, не по фактам

store/auth.js:25–28,58–65 считает локально сохранённого пользователя признаком входа и тихо глотает сбой /auth/me. При ошибках сети UI может показывать старую роль. Нужны явные состояния проверки/оффлайна, а не молчание.

Группа № 1 — по указу судьбы

ScheduleView.vue:208 жёстко выбирает group_id=1, даже если такой группы нет. В редакторе техкарты автозаполнение берёт group_id из списка, который это поле вообще не отдаёт (schedule_api.py:81–91).

Сегодня иногда вчера

store/schedule.js:54–60 и ScheduleView.vue:299–330 берут календарную дату из UTC через toISOString(). Ночью в UTC+5 местный день может стать предыдущим. Нужен единый контракт часового пояса и тест границы суток.

Ближайшие — не значит предстоящие

API сортирует занятия по убыванию времени (schedule_api.py:111); dashboard берёт первые три и не отсекает прошедшие (DashboardView.vue:98–100). Параллельные запросы разных недель могут перезаписывать ответы друг друга.

Пусто — даже когда сервер упал

store/techcard.js:17–27 подавляет ошибку загрузки, а TechcardsListView.vue:59–66 выдаёт её за «нет карт». Пагинации для API-лимита 50 нет. Нужны разные состояния loading/error/empty и загрузка следующих страниц.

На клавиатуру гостей не рассчитывали

BaseModal.vue:4–28 не управляет фокусом, Escape и атрибутами диалога. Кнопки-иконки местами без доступных названий. Демонстрационные «ИСП-21» и «201» в DashboardView.vue:48–78 подменяют отсутствующие данные.

06 / Порядок наведения приличий

Что делать, в каком порядке

Первым делом

Запереть персональные данные

Авторизация и политика доступа для участников; настоящий фильтр «моего» календаря; серверная матрица ролей техкарт. Тесты на анонима и чужую группу/карту/событие.

Сразу после

Вернуть админу его кресло

Отдельный admin-create без выдачи cookie нового пользователя; убрать токены из browser JSON; определить политику немедленного отзыва access JWT. Прогнать сценарий login → create user → me.

Следующий этап

Согласовать данные и защитить расписание

Источник истины для пользователей, инварианты слотов и импорт, транзакции, кэш-инвалидация, лимиты экспорта и загрузки. Добавить интеграционные и конкурентные тесты.

Перед запуском

Проверить поместье целиком

Исправить даты, пагинацию, загрузочные и ошибочные состояния, доступность. Затем E2E через gateway + PostgreSQL, проверка TLS/CSRF в реальном домене, восстановление из бэкапа и нагрузочный прогон.
