## 🚨 КРИТИЧЕСКИЕ ОШИБКИ БЕЗОПАСНОСТИ

### 1. **Слабые настройки JWT токенов**
- **Проблема**: JWT токены истекают через 30 минут (слишком долго)
- **Риск**: Увеличенное окно для атак с украденными токенами
- **Файл**: `backend/schedule/core/config.py:23`
- **Исправление**: Сократить до 15 минут, добавить refresh токены

### 2. **Отсутствие валидации SECRET_KEY**
- **Проблема**: Нет проверки длины и сложности SECRET_KEY
- **Риск**: Слабые ключи могут быть взломаны
- **Файл**: `backend/schedule/core/config.py:21`
- **Исправление**: Добавить валидацию минимум 32 символа

### 3. **Небезопасная обработка файлов**
- **Проблема**: Загрузка Excel файлов без проверки содержимого
- **Риск**: Возможность загрузки вредоносных файлов
- **Файл**: `backend/schedule/api/schedule_api.py:10-28`
- **Исправление**: Добавить проверку MIME-типов и сканирование

### 4. **Отсутствие rate limiting**
- **Проблема**: Нет ограничений на количество запросов
- **Риск**: DDoS атаки, брутфорс паролей
- **Исправление**: Добавить middleware для rate limiting

### 5. **Небезопасное логирование**
- **Проблема**: Возможность логирования чувствительных данных
- **Файл**: `backend/schedule/tests/test-bot-token.py:20`
- **Исправление**: Маскировать токены в логах

## ⚠️ АРХИТЕКТУРНЫЕ ПРОБЛЕМЫ

### 1. **Дублирование зависимостей**
- **Проблема**: requirements.txt содержит дублированные пакеты
- **Файл**: `backend/schedule/requirements.txt`
- **Пример**: FastAPI указан 3 раза с разными версиями
- **Исправление**: Очистить и стандартизировать зависимости

### 2. **Смешанные базы данных**
- **Проблема**: Используются SQLite и PostgreSQL одновременно
- **Файлы**: 
  - `backend/techcard/database/techcards.db` (SQLite)
  - `backend/schedule/` (PostgreSQL)
- **Исправление**: Стандартизировать на PostgreSQL

### 3. **Отсутствие единой конфигурации**
- **Проблема**: Каждый сервис имеет свою конфигурацию
- **Исправление**: Создать общий config service

### 4. **Неправильная структура микросервисов**
- **Проблема**: Сервисы слишком связаны между собой
- **Исправление**: Улучшить изоляцию и API contracts

## 🐛 ОШИБКИ В КОДЕ

### 1. **Широкие except блоки**
- **Проблема**: `except Exception` скрывает специфичные ошибки
- **Файлы**: 12 файлов содержат такие блоки
- **Исправление**: Использовать специфичные исключения

### 2. **Отсутствие валидации входных данных**
- **Проблема**: Недостаточная проверка пользовательского ввода
- **Риск**: SQL injection, XSS атаки
- **Исправление**: Добавить Pydantic валидацию везде

### 3. **Небезопасные SQL запросы**
- **Проблема**: Потенциальные места для SQL injection
- **Файл**: `backend/schedule/api/schedule_api.py`
- **Исправление**: Использовать только параметризованные запросы

### 4. **Отсутствие проверки авторизации**
- **Проблема**: Некоторые эндпоинты не проверяют права доступа
- **Исправление**: Добавить RBAC (Role-Based Access Control)
