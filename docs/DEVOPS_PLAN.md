# DevOps-аудит и план улучшений CRM College

Дата: 2026-10-06. База аудита: **main `2b52892`**, интегрирована в ветку `devops` через fast-forward. Изучены 10 новых коммитов после `67bd9d6`; локальные изменения Compose/ngrok сохранены и совмещены с новыми контрактами. SSH fetch завершился ошибкой publickey, обновление получено через HTTPS. Рабочие данные PostgreSQL и секреты сохранены.

## Что изменилось в main

| Область | Реализовано в main | Что осталось |
| --- | --- | --- |
| JWT / schedule | Удалено legacy-выпускание токенов, принимаются access JWT auth, мутации ограничены ролями | Проекция пользователей для FK участников/преподавателей, актуальность роли/блокировки, WebSocket |
| Techcard | PostgreSQL, JWT, список/POST/PUT/GET/download, адреса frontend `/api/techcards` | Владение/роли, PUT отсутствующей карты, перенос прежних SQLite-данных |
| Auth | Подключён sessions router, удалён дубль GET пользователя, исправлены cookie refresh/logout, внутренний токен аудита | Привилегированная публичная регистрация, password в query, CSRF/политика сессий |
| API | Экспорт, участники, календарь и уведомления под `/api/schedule` | Контракты с пользовательской проекцией и инвалидация cache |
| Alembic | Baseline-ревизии всех трёх сервисов | Обязательный запуск миграций, принятие прежних схем, корректный rollback enum |
| Качество | Ruff, ESLint, Prettier, блокирующие тесты/coverage в CI, gitleaks, pip-audit, Dependabot | Фиксация зависимостей/образов/actions, image scanning, полноценные PostgreSQL/E2E-сценарии |

Прежние пункты «нет CI», «нет Alembic», «sessions не подключён», «techcard всегда SQLite», «неверный frontend URL техкарт» сняты. Эта версия плана заменяет выводы первоначального аудита. Общий продуктовый план сохранён в [IMPL_PLAN.md](IMPL_PLAN.md).

## Подтверждённые ошибки и приоритеты

P0 — до публичного использования с реальными данными. P1 — следующий этап эксплуатации и интеграции. Пути backend в таблице приведены относительно `backend/`.

| ID | Приоритет | Подтверждение | Исправление и критерий готовности |
| --- | --- | --- | --- |
| AUTH-01 | **P0 — закрыто** | Публичный POST `/api/auth/register` с `role: admin` теперь получает `403`. Администратор с валидной сессией может назначать роли через тот же endpoint. | `RegisterRequest` оставляет поле для admin UI, а endpoint проверяет, что elevated role назначает только authenticated admin. Добавлен регрессионный тест. |
| ACCESS-01 | **P0 — закрыто частично** | Techcard теперь хранит `owner_id`, фильтрует список и проверяет доступ к чтению/изменению/download. WebSocket принимает только access JWT и same-origin/разрешённый Origin. | Owner-проверки и WebSocket auth реализованы; разделение broadcast-событий по правам и backfill владельцев старых карт остаются задачами IDENTITY-01/следующего этапа. |
| IDENTITY-01 | P1 | Schedule больше не ищет principal в своей БД, поэтому прежний ложный 401 исправлен. Однако teacher/participant/Telegram/calendar опираются на локальные `schedule.users`; синхронизации с auth нет. JWT-проверка также не узнаёт о деактивации/смене роли до истечения access-token. | Завершить CRM-10: единый контракт principal и явная пользовательская проекция для FK. Определить срок распространения блокировки/смены роли и правила отзыва. Проверить участников, преподавателей, уведомления и календарь на реальном auth-пользователе. |
| TOKEN-01 | P1 | Верификаторы schedule/techcard требуют type/user_id/email/role, но не требуют наличия exp. Password reset администратора передаёт пароль через query. | Требовать exp и согласованный набор claims; пароль передавать в body; проверить CSRF для cookie-auth, UTC-сравнения блокировки и очистку токенов. Пароли отсутствуют в URL/логах, токены без exp отклоняются. |
| CARD-01 | P1 | POST техкарты и PUT существующей карты работают. В PUT отсутствующей карты код всё ещё вызывает flush до заполнения обязательного tema. | Определить PUT как update-only с 404 либо корректный upsert с заполнением данных до flush; проверить на PostgreSQL. Нет 500 при корректно описанном запросе. |
| DB-01 | **P1 — исправлено** | Причина падения цикла была в оставшихся PostgreSQL enum после downgrade. | Baseline downgrade теперь удаляет `userrole`, `auditaction`, `loginstatus`, `slotstatus`, `participantstatus`; повторный цикл upgrade/downgrade проверяется в CI. |
| DB-02 | P1 | Startup трёх сервисов всё ещё вызывает create_all. Базы, созданные им, не имеют Alembic-версии; upgrade baseline на них столкнётся с существующими таблицами. | Backup → сравнение схемы → регистрация конкретного baseline только при совпадении → дальнейшие миграции. Сделать миграции отдельным обязательным шагом до запуска, удалить fallback после проверки перехода. Не использовать автоматический stamp head для неизвестной БД. |
| CACHE-01 | P1 | Cache расписания/справочников хранится в памяти и не инвалидируется после мутаций; процессы/реплики видят независимый cache. | Инвалидировать после записи, определить ключи и TTL; при масштабировании подключить общий cache/pubsub. Новые/изменённые записи сразу видны пользователям. |
